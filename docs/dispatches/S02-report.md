## 2. What was built

**`mcp-tool-shop-org/record-index`** — public, `main`, scaffold `a6bf23d`, engine
`caa9254`. Stdlib-only, no transitive surface. Eight modules, split on the axis the
ruling named: `conventions.py` (what a repo's documents MEAN — a full declaration,
validated at load, **no field has a default**) against `mechanism.py` (how the search is
TUNED — defaults, each carrying the corpus and date it was calibrated on).

facet's `tools/facet_index.py` went from **2,462 lines to a 100-line binding**; everything
that was a fact about facet is `docs/index/conventions.json`, **generated by introspection
from the live module rather than transcribed** — so the 19 seeded questions, 21 count legs
and 9 arc bounds are the values the tool was actually running on.

### (a) The twelve inline sites are declared fields

Each had no upper-case name, so a parameterisation that moved the constant block would have
carried every one into the shared package invisibly. Nine arc bounds from inside `verify()`
→ `verify.sequences`. `arc='E12'` + `range(1,17)` + `missing != [1]` →
`verify.handoff_coverage`. `range(1,16)` → `verify.experiment_coverage`. The filename
fragments → `discovery.spec_file_fragments`. `startswith("E15-")` →
`sweep.self_reference_exclude`. The second verdict vocabulary → `vocabularies.experiment_status`.
Both arc-derivation rules, the authority word, the corpus roots → declared.

### (c) `arc` identity, `experiment` grouping

`arc` stays stem-derived and stays in the primary key. `experiment TEXT` is new, non-key,
populated **709/709 rulings and 31/31 handoffs** in facet. The grouping the prefix was
wanted for costs nothing: `experiment='E10'` returns **25 rulings across 2 arcs**, and
`E08` returns 35 across 1 — which is what two ruling series numbering from 1 actually are.

### (d) Every vocabulary reports what it did not recognise

**On facet, on the first run:** `law paid_for_by` **32 recognised / 32 unrecognised**, naming
E21, E22, E23, E27–E31. facet's `PAID_RE` is frozen at `E01–E15` and facet is at E32, so
**half of facet's laws have carried a null attribution silently.** Also 12 unrecognised
ruling headers and 2 unrecognised experiment statuses. None of that was visible before.

**On armature:** `artifact kinds` **356 recognised / 0 unrecognised** — the six `.mp4`/`.mkv`
mentions that facet's map dropped in silence are indexed. `ruling headers` **38 unrecognised**,
each named — the `## N.` prose sections that are not rulings.

**⚠ And the counter failed its own test first.** My first probe was "any capitalised word"
and reported **824** unrecognised verdicts — ADJUDICATED, BASELINE, OWNER, PASS, SEAM — which
are prose. A counter that cries wolf 824 times is one every reader learns to skip, which is
the defect this section exists to prevent. Narrowed **twice, on stated rules** — the
announcing form (`is/IS <CAPS>`), then the past participle (a verdict is something *done* to
a thing) — 1434 → 592 → **260**, every remaining token a real participle the record shouts
but has not declared (AFFIRMED, AMENDED, CORRECTED, REOPENED, RESOLVED). **Then I stopped.**
The narrowing was by rule, not toward a number, and the boundary it buys is stated: facet
declares `VOID`, which is not a participle and is therefore outside the counter's population
— a blind spot of the counter, not of the parser.

**These two sections REPORT and never gate.** A diagnostic and a gate are different objects.
Whether any of them should gate is §7, question 1.

## 5. ⚠ The eight failures outside the seven — named, not edited

The full facet suite is **892 passed / 25 failed** before repair and **8 failed** after. The
25 → 8 were two regressions I caused, both real and both fixed:

* a Binding that **captured** the record root made monkeypatching `facet_index.REPO` a no-op —
  twelve resolver tests were passing against a value they were no longer setting;
* `bind()` **raised at import** when no root resolved, which took down `--help` and
  `q --db <path>` on an installed copy. E24 measured that both must work without a corpus,
  because the env var and `--db` select an **index**, never a corpus.

**The remaining 8 are structural, and both classes want a ruling rather than an edit:**

| # | tests | cause |
|---|---|---|
| 5 | `test_t32_installed_wheel.py` | they build a wheel in a **clean venv**; facet's wheel now declares `record-index`, which is **not on PyPI**. Publishing is explicitly out of this dispatch. They cannot pass until it is published. |
| 3 | `test_t30_gates_survive_optimize.py` | they **AST-scan `tools/facet_index.py`** for `run_contract` and the ANDON machinery. That code now lives in `record_index`. The property is intact; the file they scan is not where it lives. |

**Neither was narrowed, edited, or made green.** And the second class has a quieter sibling
worth naming: **`test_t19` still passes, and it now scans a shim.** Its properties — only the
certificate writer writes, every sqlite handle is read-only — are properties of code that
moved. It is green rather than red, which is worse, and it should be pointed at
`record_index` or re-homed there.

  implementations of that logic — facet's server and the package's. That is a real
  duplication of exactly the kind this extraction exists to prevent, and it is named rather
  than left to be discovered.
* **Nothing is published.** No PyPI, no release, no tag. Zero credits.
* **record-index has no test suite of its own yet.** Its behaviour is currently pinned by
  facet's 140 tests through the adapter, which is real coverage but is not the package's own.
