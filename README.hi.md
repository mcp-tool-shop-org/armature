#

**आप शॉट को रोकते हैं। मॉडल इसे शूट करता है।**

**[लैंडिंग पेज और हैंडबुक →](https://mcp-tool-shop-org.github.io/armature/)**

एक वीडियो मॉडल गति, प्रकाश और जीवन उत्पन्न कर सकता है जो कोई भी रेंडरर नहीं कर सकता। यह बताना संभव नहीं है कि *स्क्रीन पर कौन है और वे कहाँ खड़े हैं*। आर्मेचर ठीक यही प्रदान करता है: एक मानक चरित्र मेश को हेडलेस ब्लेंडर में व्यवस्थित और एनिमेट किया जाता है, और रेंडर प्रति-फ्रेम **नियंत्रण अनुक्रम** बन जाता है जिसका वीडियो मॉडल को पालन करना चाहिए - इसलिए AI द्वारा उत्पन्न वीडियो एक स्थायी मुख्य पात्र को प्रस्तुत कर सकता है जिसकी स्थिति और मुद्रा हर फ्रेम में ज्ञात हो।

**आर्मेचर छवि से वीडियो रूपांतरण है, जिसमें किसी छवि के बजाय GLB का उपयोग किया जाता है।** सब कुछ स्थानिक रूप से बनाया गया है, और मॉडल उस पर जीवन की परत चढ़ाता है। अंतिम परिणाम फुटेज होता है - फिल्म, कटसीन, चरित्र मुद्राएं और गति, कोई भी शॉट। एक गेम उस फुटेज का एक उपभोक्ता है, न कि उपकरण की सीमा।

ब्लेंडर में अपने चरित्र को व्यवस्थित करें। नियंत्रण अनुक्रम रेंडर करें। वीडियो मॉडल को उस पर जीवन की परत चढ़ाने दें। संरचना आपके द्वारा स्वामित्व वाली ज्यामिति से आती है; जीवन मॉडल से आता है; पहचान एक नामित, संस्करणित चीज़ है जो प्रॉम्प्ट और संदर्भ स्टैक में मौजूद होती है - यह कभी भी किसी भाग्यशाली फ्रेम का संयोग नहीं होता।

## स्थापित करें

```bash
pip install armature-studio
```

```bash
npm install -g @mcptoolshop/armature-studio   # the same command, as a launcher
```

```bash
armature check
armature canon --help
armature verify --help
```

स्थापना योग्य पैकेज **`armature_core`** है — इसमें गेट्स, फ्रेमिंग और टर्नअराउंड सॉल्वर, शॉट-स्पेसिफ़िक अनुबंध, चैनल गणित और पेलोड बिल्डर शामिल हैं। इनमें से प्रत्येक एक साधारण CPython के तहत आयात किया जाता है, जो उन्हें बिना ब्लेंडर के परीक्षण और पैकेज करने की अनुमति देता है।

```python
from armature_core import turnaround, framing

plan = turnaround.projection_plan(ortho=True, ortho_scale=1.1235359256161628)
```

**रेंडरिंग स्क्रिप्ट कंसोल एंट्री पॉइंट नहीं हैं, और यह जानबूझकर किया गया है।** `render_turnaround.py`, `stage_render.py` और उनके संबंधित घटक **ब्लेंडर के अपने इंटरप्रेटर** के अंदर चलते हैं — आपके पायथन पर एक कंसोल स्क्रिप्ट `bpy` को आयात नहीं कर सकती है और इसकी पहली पंक्ति में विफल हो जाएगी, इसलिए इसे शामिल करना एक ऐसा वादा होगा जिसे पैकेज पूरा नहीं कर सकता:

```bash
blender -b -P tools/render_turnaround.py -- --glb subject.glb --out renders --ortho
```

वे यहां रिपॉजिटरी में रहते हैं, जहां वह इनवोकेशन काम करता है जो लिखा गया है।
`armature_core.blender_scene` एकमात्र मॉड्यूल है जो `bpy` को आयात करता है; `armature check` इसे `needs-blender` के रूप में रिपोर्ट करता है, न कि किसी दोष के रूप में। `check` बताता है कि आपने जिस इंस्टॉलेशन को चलाया, उसके बारे में क्या सही है, न कि केवल यह कि क्या आयात किया गया: यह फ़ंक्शन-स्थानीय आयात को भी हल करता है, इसलिए यदि कोई स्रोत चेकआउट या `--no-deps` इंस्टॉलेशन OpenCV, Pillow या matplotlib को याद करता है, तो `needs-cv2` / `needs-PIL` पंक्तियाँ रिपोर्ट करता है, `UNRESOLVED:` प्रिंट करता है और 1 के साथ बाहर निकल जाता है - जहाँ पहले यह "सभी मॉड्यूल हल हो गए" एक ऐसे इंस्टॉलेशन पर प्रिंट करता था जिसके ड्राइंग फ़ंक्शन नहीं चल सकते थे। विफल पंक्ति अपवाद प्रकार और संदेश प्रिंट करती है; `--json` `module_rows` के तहत समान पंक्तियों को रखता है।

npm पैकेज एक **लॉन्चर है, पोर्ट नहीं**: किसी अन्य भाषा में थ्रेशोल्ड को फिर से लागू करना ही वह तरीका है जिससे थ्रेशोल्ड बदलता है, इसलिए यह उस पायथन पर भेज दिया जाता है जिसमें सत्य निहित है, और अस्वीकार कर देता है — जोर से, गैर-शून्य मान के साथ, उस एक कमांड के साथ जो इसे ठीक करता है — बजाय इसके कि आपके लिए कुछ भी स्थापित किया जाए।

### क्या मापा जाता है (वर्तमान आर्क)

- **Identity holds** — driven (E08: the face reads as the twin's through the shot) *and*
  unanchored (E11 wave 1: every feature to the last frame with no reference, no clip-vision,
  no driving signal). The Director's eye is the verdict of record on both.
- **The camera obeys explicit control to one pixel** on the camera-tier weights (E11 wave 3) —
  and pushes in uncommanded without it (E11 wave 1).
- **Density moves the signal, not the performance** (E10) — resampling smooths steps 41 %,
  the performance 8.6 %; adopted anyway by eye: more fps reads better.
- **A licence row is not a wiring claim** (E11 wave 2) — a mapped-Apache model and a graph that
  never loaded it produced 65 frames of noise with every gate green. Gate PAIR now exists.
- **Scene composition is seed-volatile** (E10 / E11) — identical text re-composed the world
  wholesale across seeds. **A scene claim needs two seeds before it is a property.**
- **A handed world holds** (E12) — a real room in the start frame survives to the last frame
  on two seeds on the camera tier, one-variable-attributed to the start image by field diff.
  The same tier handed a previz void held a void (E11 wave 3): worlds are authored, then kept.

## इसे चलाना

`armature_core` PyPI (ऊपर) से स्थापित होता है; **प्रयोग रिकॉर्ड और रेंडरिंग उपकरण** यह रिपॉजिटरी हैं, क्लोन किए गए और चलाए गए — कोई सेवा नहीं, कोई डेमॉन नहीं। प्रत्येक उपकरण को सीधे आह्वान किया जाता है:

```
python tools/<name>.py --help                       # the 55 CPython instruments: measurement, sheets, payload builders
blender -b -P tools/<name>.py -- <args>             # the 21 Blender-side instruments (stage_render, the rig_* tools, the
                                                    # sheet composers): headless only; `python tools/<name>.py` on one of
                                                    # these fails with `No module named 'bpy'`
pwsh -NoProfile -File .\verify.ps1                  # tests, tests under -O, package build + two clean installs (wheel + sdist), site build
```

प्रत्येक उपकरण, जिस तरह से यह चलता है, अपनी एक-पंक्ति विवरण के साथ: [docs/tools.md](docs/tools.md) (2026-09-05 को डॉकस्ट्रिंग से उत्पन्न)।

### एक रोक को पढ़ना

प्रत्येक CPython उपकरण **0** पर बाहर निकलता है जब यह वह करता है जो यह कहता है, **2** एक जानबूझकर अस्वीकृति पर (एक गेट फायर हो गया, एक आधार विफल हो गया, एक तर्क को अस्वीकार कर दिया गया) और **1** एक क्रैश पर। एक अस्वीकृति या एक क्रैश बिल्कुल एक पंक्ति प्रिंट करता है जिसका रूप `<TOOL>_HALT {json}` है, जिसका रिकॉर्ड छह कुंजियाँ रखता है - `tool`, `outcome`, `gate`, `error`, `message`, `evidence` - जहाँ `outcome` तीन वाक्यों में से एक है (`HALTED — a gate fired`, `REFUSED — the tool declined to proceed`, `FAILED — एक अप्रबंधित त्रुटि `), ` संदेश` अस्वीकृति का अपना पाठ है, और `evidence.clause` मशीन-पठनीय शब्द है जिस पर एक कॉलर शाखा बनाता है; खंड शब्दावली सूट द्वारा रखी जाती है (`tests/test_refusal_clauses.py`)। सफलता एक संकेत है जिसे उपकरण किसी प्रभाव द्वारा अर्जित करता है (`BUILD_PAYLOAD_OK`, `RIG_OK`, `ENCODE_OK`, ...), कभी भी अकेले बाहर निकलने का कोड नहीं - `blender -b -P` एक स्क्रिप्ट के अपवाद के फैलने पर 0 पर बाहर निकलता है, यही कारण है कि ब्लेंडर-साइड टूल स्थानीय हैंडलर और रिग टूल में से पांच के माध्यम से समान रोक पंक्ति रखते हैं और एक `halt.json` भी लिखते हैं उन आउटपुट के बगल में जिन्हें उन्होंने उत्पन्न नहीं किया। CPython अनुबंध का एक कार्यान्वयन `armature_core.parts.run_tool_main` है; इसका डॉकस्ट्रिंग विनिर्देश है। रिकॉर्ड को सख्त JSON के रूप में उपकरण के अपने गद्य के रूप में मुद्रित किया जाता है; जहाँ टर्मिनल का एन्कोडिंग किसी वर्ण को नहीं ले जा सकता है, पंक्ति उस वर्ण के लिए `\uXXXX` एस्केप पर वापस आ जाती है, न कि प्रिंट करने में विफल रहती है, और बाहर निकलने का कोड भी किसी भी तरह से अप्रभावित रहता है।

स्टेज सी पास (2026-09-06) के साथ तीन अस्वीकृति परिवार आए और हर जगह समान पढ़ते हैं:

- **एक उपकरण जो पहले रन के कलाकृतियों पर लिखेगा** - एक बिल्ड का ग्राफ और रिकॉर्ड, एक रेंडर के फ्रेम - खंड `output_already_exists` के साथ अस्वीकार करता है और उन्हें नाम देता है (एक बिल्ड दोनों फ़ाइलों और दोनों डाइजेस्ट को नाम देता है); `--overwrite` उन्हें बदल देता है, और सफलता रिकॉर्ड तब `out_dir_pre_existed` और `overwrote` रखता है। गेट कैनन के `out_dir_not_empty` के तहत बैठने वाला एक खर्च बिल्डर एक गैर-खाली `--out` एक गेट पहले अस्वीकार करता है और कोई ध्वज नहीं लेता है।
- **एक उपकरण जो प्रतीक्षा करता है** - एक एन्कोड, एक डिकोड, एक रेंडर, एक डाउनलोड - stderr पर एक लोअरकेस प्रगति पंक्ति प्रिंट करता है, `<tool> <stage> <done>/<total>  elapsed <e>s  bound <b>s`, प्रतीक्षा करने से पहले और बाद में (और प्रति आइटम जहाँ काम गणना योग्य है); stdout अभी भी केवल एक सफलता या रोक पंक्ति रखता है। प्रत्येक उपप्रक्रिया एक सीमा रखती है जो काम से प्राप्त होती है, और एक सीमा जो पहुंच जाती है, वह नाम से अस्वीकृति है (`ffmpeg_exceeded_the_time_bound`, `downloader_exceeded_the_time_bound`) जो डिस्क पर आंशिक कार्य को नाम देती है और कभी भी पुनः प्रयास नहीं करती है - भुगतान किए गए पथ पर एक पुनः प्रयास ऐसे क्रेडिट खर्च करता है जिनके पास कोई क्षतिपूर्ति नहीं है।
- **एक गेट जो आउटपुट निर्देशिका के मौजूद होने के बाद फायर करता है** कहता है: अस्वीकृति निर्देशिका को नाम देती है, कहती है कि इसमें आंशिक कार्य है और यह परिणाम नहीं है, और समर्थित अगले चरण को बताती है।

## स्थायी नियम जो यहां सब कुछ निर्धारित करते हैं

**कभी भी गैर-व्यावसायिक मॉडल का उपयोग न करें—यहां तक ​​कि प्रयोगों में भी नहीं।** सीसी-बीवाई-एनसी, केवल अनुसंधान और केवल शैक्षणिक लाइसेंस पूरी तरह से प्रतिबंधित हैं। एक प्रतिबंधित मॉडल पर आधारित निष्कर्ष को त्याग दिया जाना चाहिए, इसलिए यह कभी शुरू नहीं होता है।

**मेट्रिक्स नैदानिक ​​उपकरण हैं; निर्देशक निर्णय लेते हैं।** स्क्रीन पर दिखाई देने वाला आंकड़ा समान चरित्र है या नहीं, यह निर्धारित किया जाता है, और कोई भी मीट्रिक इसका सटीक अनुमान नहीं लगाता है। प्रत्येक पीढ़ी के प्रयोग में एक **नियंत्रण | आउटपुट | संदर्भ | उत्पत्ति** शीट बनाई जाती है, इससे पहले कि कोई भी संख्या उद्धृत की जाए।

**क्लाउड क्रेडिट खर्च करने से पहले सीमित कर दिए जाते हैं।** खर्च किए गए क्रेडिट को वापस नहीं किया जा सकता, इसलिए प्रत्येक विनिर्देश में इसकी सीमा अग्रिम रूप से बताई गई है।

**मार्ग बताते हैं कि उनके साथ क्या शामिल है** (निर्देशक का निर्णय, 2026-08-12)। किसी तीसरे पक्ष के माध्यम से जाने वाले किसी भी मार्ग में उसके प्रदाताओं के डेटा उपयोग और प्रशिक्षण की स्थिति, उसकी एआई-सामग्री प्रकटीकरण आवश्यकताओं और उसकी वॉटरमार्क नीति का दस्तावेजीकरण किया जाता है, जो लाइसेंस मानचित्र के प्राप्त दस्तावेजों पर आधारित होती है। पूरी तरह से स्थानीय मार्गों में कहा गया है कि कुछ भी रिग से बाहर नहीं जाएगा। यदि किसी मार्ग में उसके प्रकटीकरण नोट नहीं हैं, तो वह पूरा नहीं माना जाएगा—पहला एप्लिकेशन ई13 के विनिर्देश का उपयोग करता है।

## विश्वास और खतरे का मॉडल

पूरी नीति [SECURITY.md](SECURITY.md) में दी गई है, जिसे वृक्ष के सापेक्ष मापा जाता है, न कि केवल बताया गया है। संक्षिप्त रूप:

- **Data touched** — meshes, renders, videos, images and JSON on local disk, at paths you pass
  on the command line, plus `docs/index/armature.db`, a SQLite index *derived* from this repo's
  own markdown. Canonical assets are consumed read-only from sibling trees and never written to.
- **Data NOT touched** — no credentials of any kind: none are read, stored or transmitted, and
  a sweep of every tracked file for provider-prefixed keys, tokens, private-key blocks and
  inline secret assignments returns zero matches. **No telemetry, analytics or usage counting**
  is collected or sent; there is no opt-out because there is nothing to opt out of.
- **Network egress** — no Python networking library is imported anywhere in `tools/` or
  `tests/`. Two tools shell out to `curl.exe` to download the files listed in a dump *you*
  paste in, from a generation *you* submitted. Nothing else here makes a network call.
- **Permissions** — ordinary user permissions. No elevation, no service installation, no
  registry or system-settings writes.
- **The sharp edges, disclosed rather than claimed away** — file operations are not sandboxed;
  a tool writes wherever its arguments say. Unexpected failures print a raw traceback.
  Deliberate refusals do not: every gate raises a typed error carrying the measurement that
  fired it, and **none of them is an `assert`** — the suite runs a second time under `-O` in CI
  to prove they still raise.
- **Support status** — `main` is the only supported state. Tagged releases exist (`v0.4.0`
  is current); there is no backport policy and no SLA.

**शिप गेट।** [SHIP_GATE.md](SHIP_GATE.md) में वास्तविक रूप से मौजूद कठोर गेट ए-डी शामिल हैं, जिसमें प्रत्येक पंक्ति या तो उसके प्रमाण के साथ जांच की जाती है या उसके गुणों के आधार पर छोड़ दी जाती है। सॉफ्ट-गेट पहचान आइटम ईमानदारी से सूचीबद्ध हैं, जिसमें वह भी शामिल है जो अभी भी खुला है।
