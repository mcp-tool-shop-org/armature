#

**你挡住了镜头。模型拍摄了画面。**

**[登陆页面和手册 →](https://mcp-tool-shop-org.github.io/armature/)**

一个视频模型可以产生渲染器无法产生的运动、光线和生命力。它不能告诉我们*屏幕上是谁，以及他们站在哪里*。armature 恰好提供了这一点：一个规范的角色网格被放置并以无头 Blender 的形式进行动画处理，然后渲染结果成为每一帧的**控制序列**，视频模型必须遵守该序列——因此，人工智能生成的视频可以呈现出一个持续存在的主要角色，并且在每一帧中都知道角色的位置和姿势。

**armature 是图像到视频的转换，使用 GLB 文件代替图像。** 所有空间元素都是由人工创作的，模型在其之上赋予生命。最终交付的是素材——电影、过场动画、角色姿势和动作，以及任何镜头。游戏只是该素材的一种应用方式，而不是该工具的边界。

在 Blender 中设置你的角色。渲染控制序列。让视频模型在其之上赋予生命。结构来自你拥有的几何体；生命来自模型；身份是一个命名的、版本化的事物，它存在于提示词和参考堆栈中——而不是幸运帧的偶然结果。

## 状态：该论点在产品层面进行衡量

成立于 **2026-08-10**。完成了十二个实验，并且该论点已经从*测试中*发展到**在产品层面上进行衡量**：角色已经在屏幕上跳舞了两次——一次是由它自己的骨骼驱动的，另一次是自由状态的；一个构建好的世界现在保留到了两个种子（E12）上的最后一帧，所有这些都由导演亲自判断。该项目的审计报告位于
[docs/audit-first-arc.md](docs/audit-first-arc.md)；自 2026-08-12 以来的状态是一个学习型单仓库——实验证明了可行路径，没有哪条路线会因为惯性而成为标准（CLAUDE.md）。

### 当前阶段所衡量的内容

- **身份保持一致**——驱动（E08：在整个镜头中，面部看起来像双胞胎）*和*未锚定（E11 阶段 1：所有特征都保留到最后一帧，没有参考、没有剪辑视觉效果、没有驱动信号）。导演的判断是记录中的最终结论。
- **相机服从明确的控制，精确到像素级别**，在相机层权重上（E11 阶段 3），并且在没有明确指令的情况下进行移动（E11 阶段 1）。
- **密度影响信号，而不是性能**（E10）——重采样使步骤平滑了 41%，性能提高了 8.6%；尽管如此，仍然通过视觉效果进行了采用：更高的帧率看起来更好。
- **许可行不是布线声明**（E11 阶段 2）——一个映射的 Apache 模型和一个从未加载它的图表产生了 65 帧的噪声，并且所有门户都显示为绿色。现在存在“门”配对。
- **场景构图是基于种子的**（E10 / E11）——相同的文本重新构建了整个世界，跨越不同的种子。**在拥有两个种子之前，场景声明才会被视为一种属性。**
- **一个构建好的世界得以保留**（E12）——一个真实的房间在起始帧中存在，并且保留到相机层上的最后一帧，只有一个变量被归因于起始图像，通过字段差异进行比较。相同的层在一个空的预览环境中保留了一个空虚（E11 阶段 3）：世界是人工创作的，然后被保留下来。
- **目录中的 6.0 / uni_pc 是相机层的基线**（E12）——继承的 3.5 / euler 前提落到了它自己的级别：在目录设置中，相同的种子既失去了头部又长出了肢体，并且能够将人物保留到第 80 帧。成本是已知的——更强的附着力将**未限定的身份条款**应用于两个种子中的一个上的群众；以主题为范围的提示是推广的杠杆。

### 当前阶段不衡量的内容

- **手臂和手部快速移动。** 在两个种子和两种设置（E12）下，仍然无法通过 f80 测试。
操纵杆的重新设计以“**注重呈现效果**”为先——腕部和摄像机的定位，由导演根据 GLB 诊断得出（爪子是一种投影伪像，而不是网格损伤），然后采用网格修复作为备用方案，绝不会将其作为首要措施。
- **摄影世界中的相机声明。** 在所有四个 E12 片段中，水平线检测次数为 0/81，表明检测器需要一个该世界没有的缝隙——在提交之前已注册为盲点，并且从未转换为相机结果。在对真实房间进行任何相机编号读取之前，必须提供一个“**无缝相机工具**”。
- **叙事库**（请参阅 #7）：关键帧终点、每个片段的提示、视频时间区域条件、相机嵌入——采用并根据需要获得许可，未经测试。

否定的答案在这里仍然是完全成功的——E11 的严重失败促成了三个关卡、两条规则以及下一个作品的确切形状，并且路线图在任何证据出现之前就已说明了这一点。

## 此仓库的工作方式

- [CLAUDE.md](CLAUDE.md)——如何在此处工作：三个角色、每个角色所遵循的规则以及不可谈判的内容（许可证关卡、有限额度，身份通过视觉判断）。
- [docs/ROADMAP.md](docs/ROADMAP.md)——整个构建过程，按会话划分，并提前命名了漂移触发点。
- `docs/experiments/`——每个非平凡的更改都将作为编号实验进行：**先制定规范，然后进行工作 → 完成后提交报告 → 最后由顾问做出裁决。**
- `docs/license-map.md`——经过验证的商业用途地图。如果没有检索到的许可证文档，任何内容都不能进入流水线。

该方法继承自 [facet](../facet)，在那里它得到了应用：在 facet 的初始会话中，有六个继承的声明被证明是虚假的，每个声明都在几分钟内完成，因为每个声明都与可运行的代码相邻。armature 是 facet 的下游——facet 剪切并绘制图形；armature 对其进行分阶段处理和执行。

## 如何运行它

无需安装任何东西。这是一个你可以克隆并运行的仓库——没有软件包，也没有服务或守护进程。每个工具都直接调用：

```
python tools/<name>.py --help                       # measurement, sheets, payload builders
blender -b -P tools/stage_render.py -- <args>       # staging and render, headless only
pwsh -NoProfile -File .\verify.ps1                  # tests, tests under -O, site build
```

| | |
|---|---|
| 平台 | 在测试机上使用 Windows 11（Omen 45L、RTX 5090）。密封测试也在 CI 中的 `ubuntu-latest` 上运行；依赖于 Blender 的测试会在没有 Blender 时“明显跳过”，而不是静默通过。 |
| Python | 3.13+——CI 使用 3.13，测试机的 venv 使用 3.14。测试依赖项包括 numpy、pillow、pytest 和 opencv（固定到测试机的版本，因为姿态栅格化测试会断言字节稳定的栅格化）以及 matplotlib。 |
| Blender | 5.2，仅限无头模式。实时 GUI 会话会在没有记录参数的情况下产生伪像，并且无法重现其输出的配方就不是一个有效的配方。 |
| Node | 22，仅用于 `site/` 下的站点。 |
| 生成 | 在 Comfy Cloud 上运行，并由操作员提交；渲染和测量在本地进行。 |

许多工具和文档中都嵌入了绝对的测试机路径——它们不是秘密，但这意味着大多数工具未经修改就无法在其他机器上运行。

## 塑造此处所有内容的基本规则

**绝不允许使用任何非商业模型，包括用于实验。** CC-BY-NC、仅限研究和仅限学术用途的许可证将被完全禁止。如果基于被禁止的模型得出结论，则该结论必须被丢弃，因此它永远不会开始。

**指标是诊断工具；导演进行判断。** 屏幕上的人物是否与原始角色相同才是关键，没有任何指标可以近似地表示这一点。每个生成实验都会在引用任何数字之前构建一个“**控制 | 输出 | 参考 | 出处**”表格。

**云端积分在使用前必须进行限制。** 使用过的积分无法撤销，因此每个规范都提前说明了每个臂的上限。

**路线会显示与其一起使用的内容**（导演裁决，2026-08-12）。任何通过第三方层级的路线都会记录其提供商的数据使用和训练策略、AI 内容披露义务以及水印政策，这些都基于许可证地图中检索到的文档。完全本地的路线声明没有任何内容会离开测试机。如果缺少披露说明，则该路线不完整——第一次应用将使用 E13 的规范。

## 信任和威胁模型

完整的策略在 [SECURITY.md](SECURITY.md) 中，它是根据树结构进行测量的，而不是断言的。简而言之：

- **涉及的数据**——本地磁盘上的网格、渲染、视频、图像和 JSON 文件，位于您在命令行中提供的路径下，以及 `docs/index/armature.db`，这是一个从该仓库自身的 Markdown 文档派生出的 SQLite 索引。规范资源以只读方式从同级目录读取，且绝不会写入。
- **不涉及的数据**——任何类型的凭据：既不读取、也不存储或传输，并且对每个已跟踪的文件进行扫描，以查找带有提供商前缀的密钥、令牌、私钥块和内联密钥赋值，结果为零个匹配项。**不收集或发送任何遥测数据、分析数据或使用情况统计信息**；由于没有任何内容需要选择退出，因此无需提供选择退出的选项。
- **网络输出**——在 `tools/` 或 `tests/` 中的任何位置都没有导入 Python 网络库。两个工具会调用 `curl.exe` 来下载您粘贴的转储中列出的文件，这些文件来自您提交的版本。除此之外，没有任何其他操作会进行网络调用。
- **权限**——普通用户权限。无需提升权限、安装服务或写入注册表或系统设置。
- **明确说明而非隐瞒的潜在问题**——文件操作没有被沙箱化；工具会将数据写入其参数指定的任何位置。意外错误会打印原始回溯信息。有意的拒绝不会发生：每个检查点都会引发一个带有触发它的测量值的类型化错误，并且**它们都不是 `assert`**——该套件在 CI 中第二次运行于 `-O` 下，以证明它们仍然会引发错误。
- **支持状态**——`main` 是唯一受支持的状态。没有发布渠道、回溯策略或 SLA（服务级别协议）。

**发布门控。**[SHIP_GATE.md](SHIP_GATE.md) 包含实际存在的 A–D 四个硬性门控，每一行都附带其证据进行检查，或者根据其自身的情况被跳过。软性门控的身份项目也如实列出，包括仍然开放的一个。
